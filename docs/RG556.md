# Anbernic RG556 branch

This branch (`rg556` on savemosca/Mother3Recomp) is josiahg2502-glitch/Mother3Recomp
plus what the RG556 Android port (savemosca/Mother3Recomp-Android) added. It
replaces that port. Pieces useful to every player go upstream as pull
requests; the rest stays here.

## Building for the RG556

```sh
python3 tools/setup_deps.py          # engine, recomp-ui, rcheevos at their pins
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --target gba_recompile
GBA_RECOMPILE=build/gbarecomp_build/gba_recompile tools/regen.sh <rom.gba> <gba_bios.bin>
cd android && gradle :app:assembleDebug -PgbaAbis=arm64-v8a -Pm3Device=rg556
```

The ROM and BIOS are imported on the device, never packaged. Install over
the old port with `adb install -r`: both use the application id
`com.ylports.mother3recomp.en.dev`, and a build signed with the same key
keeps app-private storage.

## Moving from the old port

`LegacyFiles` renames the old port's `roms/mother3_en.*` (ROM, battery save,
suspend state, its `.ra` sidecar and marker) and `suspend-backups/` to this
app's `mother3_en_v13.*` once, never overwriting. `bios/gba_bios.bin`,
`config.ini` and `retroachievements.ini` already have the same paths.

The suspend state resumes only on the stock ROM image, so the Android setup
writes `m3_hq_audio = 0` when the key is missing (the native default is HQ
on) and keeps an existing `[Audio] enhanced` choice. Switching HQ later asks
first when a suspended game is waiting.

Rehearsed on 2026-10-26 with a test application id and copies of a player's
files: everything moved, the state resumed at its frame, 4127 frames idle
with 4 late, Enhanced audio live 98.6% of the time.

## Tools

- `tools/rg556-health.sh`: one line per recent session (late frames,
  stalls, audio gaps, interpreted code), read-only on the device.
- `tools/rg556-idle-bench.sh`: the same suspend state, idle for N seconds,
  on a build installed under another application id; `WIDE=1` turns
  widescreen on. Compare builds with it before installing over a player's
  app.

## Lessons

- An engine update can make suspend states unloadable: check that a test
  app resumes a real player's state before installing. The 2026-10-25
  update hit two such changes (snapshot v4, fingerprinted resume markers).
- Never run the bench while the player plays: it launches apps and presses
  keys. Send HOME so the game flushes its state, and back the state up,
  before installing over the player's app.
- Copy saves with `cp -p`: the old-save warning reads file dates.

## Open points

- Widescreen: actors in real looping maps (only tested with the loop bits
  forced); other overlays (fog, darkness) on layers other than a blended
  BG1; the off-screen actor flag now flips 22 px earlier while widescreen
  is on (no gameplay effect seen).
- Suspend state: not cloud synced; no check that it loads before an engine
  update.
- Audio: startup drops 60-80 ms; `audio_stretched_ms` is missing from the
  session health line; a 50 ms target could suit rhythm combos.
- RetroAchievements unlocks earned offline are lost if the game quits before
  reconnecting.
- Upstream: mstan/gbarecomp#66 (drop the v2 loader from the patch when it
  lands); the frame-pacer debt repayment is not proposed yet; mstan#39
  (closing IRQs that never iret) is kept in reserve for hangs.
- Icon: this app uses josiah's; the old port's "M" icon is not carried over.
